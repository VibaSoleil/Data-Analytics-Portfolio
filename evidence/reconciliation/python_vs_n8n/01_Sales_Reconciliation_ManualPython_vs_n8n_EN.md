# 1. Objective

This document aims to verify that all Key Performance Indicators (KPIs) generated by the **Sales ManualPython** module are identical to the results obtained from the **n8n automation pipeline**.

The reconciliation is performed to ensure that the automated process in n8n successfully replicates the ManualPython process consistently and in a validated manner.

---

# 2. Scope of Reconciliation

The scope of the reconciliation includes:

* Total Sales Revenue
* Total Transaction
* Total Unit Sold

All KPIs are verified for each monthly period in the dataset.

# 4. Source Code Verification

The investigation shows that the two outputs have different functions.

**ManualPython** produces a Sales report in the form of a monthly sales summary through transaction aggregation.

Meanwhile, the **n8n pipeline** produces a cleaned transaction dataset (`Company_Data_Cleaned_n8n.csv`) as the primary output of the automated process.

The dataset is then used to recalculate Sales KPIs so that they can be independently compared against the ManualPython Sales Report.

ManualPython

SCRIPT/
ODC_Bag8_FinalReport_02_SALES_Professional.py

n8n Pipeline

SCRIPT/
ODC_Bag8_FinalReport_02_SALES_Professional_n8n.py

The ManualPython script produces the Sales report through transaction aggregation, while the n8n script produces the transaction dataset resulting from the automation pipeline, which is then recalculated as the basis for the reconciliation process.

---

# 5. Reconciliation Methodology

Because the structures of the two artifacts are different, the reconciliation is not performed through direct file comparison.

The method used is:

1. Read the `Company_Data_Cleaned_n8n.csv` dataset.
2. Group transactions by period (YYYY-MM).
3. Recalculate:

   * Total Revenue
   * Total Transaction
   * Total Unit Sold
4. Compare the recalculated results with the ManualPython Sales Report.
5. Verify the consistency of all KPIs.
