### D. Important Technical Note

During the validation process, it was identified that the script `ODC_Bag8_FinalReport_04_CUSTOMER_Professional_n8n.py` uses the Linux path structure (`/app/...`) as the location for the input dataset and analysis output.

At the initial stage, the script was executed using native Python on Windows (`py`), resulting in a file reading failure because Windows does not recognize the Linux path structure (`/app/...`). As a result, the validation process stopped during the dataset reading stage with a `FileNotFoundError` message.

After investigation, it was determined that the script was indeed designed to be executed inside a Docker Container, where the Windows project directory:

```text
D:\Project_01_Data_Analyst
```

is bind-mounted as:

```text
/app
```

within the Linux environment.

As a corrective action, the validation process was subsequently executed directly inside the container using the following command:

```text
docker exec python-project-container python /app/SCRIPT/ODC_Bag8_FinalReport_04_CUSTOMER_Professional_n8n.py
```

After using the appropriate environment, the script successfully read the n8n pipeline dataset, completed the entire analysis process from Part 1 through Part 6, and generated all required output artifacts for the reconciliation process.

Therefore, it can be concluded that the issue was not caused by an error in the Customer script or the n8n pipeline dataset, but rather by the difference in execution environments between Windows and Docker (Linux). After being executed in the appropriate environment, the entire Customer analysis process was completed successfully without issues, and all outputs were generated as the basis for Customer Reconciliation.

## 7.1 Finding 01

### Script Uses Linux Path

**Finding**

The Professional n8n script uses the Linux path structure.

Example:

```text
/app/OUTPUT/Company_Cleaned_n8n.csv
```

However, this path is not recognized on Windows, preventing the script from being executed directly using Python on Windows.

**Impact**

The script generated the following error:

```text
FileNotFoundError
```

because the `/app/...` directory was not available on the Windows operating system.

**Action**

The script was not executed using Python on Windows. Instead, it was executed directly inside the Docker Linux Container using the following command:

```text
docker exec python-project-container \
python /app/SCRIPT/ODC_Bag8_FinalReport_04_CUSTOMER_Professional_n8n.py
```

**Status**

RESOLVED

## 7.2 Finding 02

### Python API Container Not Running

**Finding**

The container:

```text
python-project-container
```

had the status:

```text
Exited (3)
```

so the Python API could not be used.

**Cause**

The container was still using:

```text
uvicorn main:app
```

while the `main.py` file was located in:

```text
/app/SCRIPT/
```

**Action**

The container was recreated using the following configuration.

**Working Directory**

```text
/app
```

**Command**

```text
uvicorn SCRIPT.main:app
```

After the change was applied, the Python API successfully started again.

**Status**

RESOLVED
