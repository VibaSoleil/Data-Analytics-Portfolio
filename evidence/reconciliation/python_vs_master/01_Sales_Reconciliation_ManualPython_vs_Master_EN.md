# 4. Source Code Verification

Investigation of the source code shows that the two outputs serve different purposes.

## Manual Python

Source:

```text
SCRIPT/
ODC_Bag8_FinalReport_02_SALES_Professional.py
```

Uses the following SQL query:

```sql
SELECT

DATE_FORMAT(tanggal_transaksi,'%Y-%m') AS bulan,

SUM(total_harga) AS total_omzet,

COUNT(id_transaksi) AS jumlah_transaksi,

SUM(jumlah) AS jumlah_produk_terjual

FROM transaksi

GROUP BY bulan

ORDER BY bulan
```

The resulting output is a monthly sales summary.

---

## Master Dataset

Source:

```text
SCRIPT/
ODC_Bag8_FinalReport_00_SALES_MASTER_Professional.py
```

Uses an SQL query that retrieves detailed transactions together with additional information from the Produk, Pelanggan, and Keuangan tables.

The dataset is then directly exported as the Sales Master Dataset.

Therefore, the Sales Master functions as the **audit layer** and **canonical dataset**, while Sales Manual is an **analytical report** built from aggregated transaction data.

---

# 5. Reconciliation Methodology

Because the two artifacts have different data structures, the reconciliation is not performed through direct file comparison.

The methodology used is as follows:

1. Read the Sales Master Dataset.
2. Group transactions by period (YYYY-MM).
3. Recalculate:

   * Total Revenue
   * Total Transaction
   * Total Unit Sold
4. Compare the recalculated results with the Sales Report Manual Python.
5. Verify the consistency of all KPIs.

This method ensures that all KPIs in the Sales Report can be independently reproduced from the Master Dataset.
